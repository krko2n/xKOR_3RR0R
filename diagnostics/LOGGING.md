# xKOR_3RR0R Logging & Crash Reporting System

## Overview

The xKOR_3RR0R project has a comprehensive **automatic error logging and crash reporting system** with **git auto-commit integration**.

This system captures:
- Uncaught JavaScript exceptions
- Unhandled promise rejections
- Rust panics
- System crashes (Hyprland/compositor)
- Terminal/PTY failures
- Backend errors

All critical errors are:
1. Logged to disk (`diagnostics/logs/`)
2. Full crash reports generated (`diagnostics/crashes/`)
3. **Automatically committed to git** for debugging

---

## Architecture

### Frontend (JavaScript)

**File**: `src/js/error-logger.js`

Captures:
- `window.onerror` → Uncaught exceptions
- `window.onunhandledrejection` → Unhandled promises
- Manual crashes via `window.reportCrash()`
- Fatal errors via `window.reportFatal()`

All errors are sent to Rust backend via Tauri IPC: `log_frontend_error`

### Backend (Rust)

**File**: `src-tauri/src/commands/logging.rs`

Provides:
- `log_frontend_error()` - IPC command for frontend errors
- `log_backend_error()` - Internal Rust error logging
- `log_panic()` - Panic hook integration
- Automatic `crash-logger.sh` invocation

### Crash Logger (Bash)

**File**: `diagnostics/crash-logger.sh`

Captures:
- Full system state (kernel, memory, disk, processes)
- User session state (PAM, XDG_RUNTIME_DIR)
- Compositor state (Hyprland sockets)
- Systemd service status
- Recent logs
- **Git auto-commit** with structured commit messages

### Integration Points

- **Tauri panic hook**: `lib.rs` installs `std::panic::set_hook()`
- **Hyprland launcher**: `os/bin/start-hyprland` calls crash-logger on failures
- **Frontend global handlers**: `error-logger.js` loaded before all other scripts
- **OS mode systemd**: Service failures trigger crash reports

## Directory Structure

```
diagnostics/
├── crash-logger.sh           # Main crash reporting script
├── install-diagnostics.sh    # Setup script
├── logs/                     # Runtime logs (gitignored, too large)
│   ├── backend/              # Rust backend logs
│   ├── frontend/             # JavaScript/Tauri logs
│   ├── compositor/           # Hyprland/X11 logs
│   ├── terminal/             # PTY/bash logs
│   ├── runtime/              # Application runtime logs
│   ├── install/              # Installation logs
│   ├── upgrade/              # Upgrade logs
│   └── system/               # System service logs
├── crashes/                  # Full crash reports (tracked in git)
└── errors/                   # Error logs (tracked in git)
```

### What's Tracked in Git?

- ✅ `crashes/` - Full system state dumps
- ✅ `errors/` - Error reports
- ❌ `logs/` - Too large, keep local only

## Usage

### Frontend Error Reporting

```javascript
// Automatically captured
throw new Error('Something went wrong');

// Promise rejection - automatically captured
fetch('/api').then(data => { throw 'Failed' });

// Manual crash report
window.reportCrash('user_action', 'User clicked invalid button', { buttonId: 123 });

// Fatal error with auto-commit
window.reportFatal('Database connection lost', new Error('Connection timeout'));
```

### Backend Error Reporting

```rust
use crate::commands::logging;

// Log backend error
logging::log_backend_error("database", "Connection timeout", &format!("{:?}", err));

// Panics are automatically captured
panic!("Unexpected state!");  // Will be logged and committed
```

### Bash Script Integration

```bash
# Capture crash with full system state
./diagnostics/crash-logger.sh crash "compositor" "Hyprland socket init failed"

# Capture error (lighter weight)
./diagnostics/crash-logger.sh error "authentication" "Login failed for user"

# Cleanup old logs
./diagnostics/crash-logger.sh cleanup
```

## Git Auto-Commit

When a crash occurs, the system automatically:

1. Generates full crash report in `diagnostics/crashes/TIMESTAMP_crash.log`
2. Stages the file: `git add diagnostics/crashes/...`
3. Creates structured commit:

```
crash: 2026-05-24_13-04-44 - rust_panic

Automatic crash report generated by diagnostics/crash-logger.sh

Crash type: rust_panic
Timestamp: 2026-05-24_13-04-44
Log: diagnostics/crashes/2026-05-24_13-04-44_crash.log

This is an automated diagnostic commit.
Review the log file for full system state at crash time.
```

### Viewing Crash History

```bash
# List all crash commits
git log --grep="^crash:" --oneline

# Show crash report
git show HEAD:diagnostics/crashes/TIMESTAMP_crash.log

# Pull latest crash reports before debugging
git pull
```

---

## Log Retention

- **Logs (`diagnostics/logs/`)**: Automatically cleaned after **7 days**
- **Crashes (`diagnostics/crashes/`)**: Kept in git permanently (until manually pruned)
- **Errors (`diagnostics/errors/`)**: Kept in git permanently

To manually clean up:
```bash
./diagnostics/crash-logger.sh cleanup
```

## Troubleshooting

### Logs Not Being Created?

1. Check directory permissions:
   ```bash
   ls -la diagnostics/logs/
   ```

2. Verify crash-logger is executable:
   ```bash
   chmod +x diagnostics/crash-logger.sh
   ```

3. Check if PROJECT_ROOT is set correctly:
   ```bash
   PROJECT_ROOT=$(pwd) bash diagnostics/crash-logger.sh crash "test" "Testing"
   ```

### Git Commits Not Working?

1. Ensure diagnostics/ is not in .gitignore:
   ```bash
   git check-ignore diagnostics/crashes/
   ```

2. Verify git repo is initialized:
   ```bash
   git status
   ```

3. Check if script has git access:
   ```bash
   cd /opt/xkor_3rr0r && git add diagnostics/crashes/*.log
   ```

### Frontend Errors Not Logged?

1. Check browser console for `[xKOR] Error logger initialized`
2. Verify Tauri IPC is working:
   ```javascript
   window.__TAURI__.core.invoke('log_frontend_error', { /* ... */ })
   ```

3. Check backend logs:
   ```bash
   tail -f diagnostics/logs/frontend/*.log
   ```

## Development vs Production

### Development Mode (tauri dev)
- Logs go to `./diagnostics/logs/`
- Git auto-commit works if run from repo root
- Console errors visible in terminal

### Production Mode (OS mode)
- Logs go to `/opt/xkor_3rr0r/diagnostics/logs/`
- Git auto-commit always works
- Systemd captures stderr to journald
- View with: `journalctl -u xkor-login -f`

---

## Performance Impact

- **Minimal overhead**: Logging is async, doesn't block UI
- **File I/O**: Appends only, no reads during runtime
- **Git commits**: Run in background process, non-blocking
- **Crash reports**: Only generated on actual crashes (rare)

---

## Security Considerations

- **No sensitive data**: Logs don't capture passwords or secrets
- **Local only**: Logs never sent over network
- **Git tracked**: Crash reports visible in repo history
- **Permissions**: Logs written with current user permissions

If handling sensitive data:
- Review crash reports before committing to public repos
- Consider adding `.git/hooks/pre-commit` to scan for secrets
